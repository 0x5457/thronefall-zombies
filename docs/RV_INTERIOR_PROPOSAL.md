# 房车内部与布置提案

> 状态：PARTIAL（RV-02 进入/退出与独立切面已接入并通过浏览器检查；布置和功能家具仍未实现）  
> 范围：只讨论首章中的一辆房车，不扩展为可进入的开放世界建筑系统。

## 1. 结论

这个方向值得做，而且和 PINEFALL 的核心愿景很契合。外部营地负责“守住家”，房车内部负责“把家变成自己的家”，能让木材、零件和每天的准备不只是数字。

但它不能只是一个装饰菜单，也不能成为躲进房车就跳过夜战的安全屋。建议把它定义为一个很小、很有情绪的**室内准备空间**：进入、布置、获得有限的准备优势，然后回到外部营地完成防守。

必须守住三条规则：

1. 室内布置要让玩家做选择，而不是无成本地增加所有属性。
2. 房车外部必须能看见内部成长，例如窗光、窗内剪影和屋内道具变化。
3. 进入房车不能跳过敌人、夜晚、资源消耗或营地受损。

### 已确认决策

- 首版只允许在白天进入房车。
- 夜晚角色必须留在外部营地参与防守，不能通过进入房车暂停或规避战斗。

## 2. 当前基线与缺口

**RV-02 实现更新**：`src/interior.ts` 已提供床铺、厨房、餐桌、窗帘与暖灯的独立切面；白天门口 E/按钮进入，WASD 过道移动，E/Esc/按钮退出原门外位置。室内冻结日间预算，禁建造/入夜，夜间拒绝进入。当前直接切换视图，尚无镜头过渡；下文未落地部分继续作为目标，不代表已有家具玩法。

以下是实现前的基线记录：

设计目标仍然是“白天探索与建设，夜晚亲自守住房车”。现有代码中的房车在 `src/world.ts` 里是一个整体模型，角色移动在 `src/main.ts` 中会把它当作不可穿过的碰撞体。当前状态只有室外昼夜循环，没有室内模式、家具数据、门交互或房车内部存档数据。

因此，这不是给房车加一扇门就能完成的小装饰，而是需要补充一个受控的室内状态。不过它不需要另一张开放地图，也不需要复杂的建筑引擎。

## 3. 推荐的玩家闭环

### 白天

1. 角色走到房车侧门，出现 `E 进入房车`。
2. 按下 `E`，经过很短的镜头过渡进入室内切面。
3. 玩家在狭长的房车空间里查看已有物品，进入布置模式。
4. 选择家具或装饰，看到占地、成本和可产生的效果。
5. 放置、旋转或移动后退出布置模式。
6. 从门口离开，回到门外原位置；房车外观和窗户反馈同步变化。
7. 玩家继续采集、建造、远征，然后主动迎接夜晚。

### 夜晚

首版不允许进入房车布置。门旁显示“夜晚留在外面守住营地”，玩家必须处理来袭者。

这样做的理由不是限制想象力，而是避免两个严重问题：玩家通过室内暂停规避战斗，或者在室内看不到外面的攻击反馈却让营地继续掉血。室内生活感可以通过夜间窗光、窗内剪影、收音机噪声和门缝光表现出来。

### 时间规则

推荐首版进入室内后暂停日间准备倒计时，但不返还已经消耗的远征时间。室内布置属于明确的准备操作，不应该让玩家因为看家具说明而损失不可读的秒数；真正需要付出的代价是木材、零件和有限的功能位置。

如果以后希望室内也承担夜间避险，就必须让时间继续流动、让房车继续受攻击，并清楚显示外部状态。这应当是后续方案，不应和第一次室内实现绑定。

## 4. 室内呈现方式

推荐采用“逻辑上同一辆房车，渲染上独立的小型切面”：

- 进入时镜头向房车门移动，墙体或车顶以切面方式淡出，而不是加载一张完全无关的地图。
- 室内使用固定的正交俯视/轻微等距视角，镜头比室外更近，保证狭窄空间仍然能看清家具。
- 室内不参与室外敌人的寻路和碰撞，避免把房车内部变成新的战斗地图。
- 退出时从门口返回，不把角色随机传送到车外另一侧。
- 室内和室外使用同一套低多边形、轻像素化材质；暖灯、奶白车壁、橙色细节和绿色布料延续现有美术方向。

不推荐第一版做完全自由的 3D 室内漫游。房车本身很窄，完全自由的相机和碰撞会花费大量时间，却不一定比一个清楚的切面更有生活感。

## 5. 空间布局草案

室内不是一间大房子，而是几块有明确用途的小区域：

| 区域 | 固定内容 | 布置限制 |
|---|---|---|
| 入口缓冲区 | 门、过道、门边挂钩 | 必须保持通行，不能放家具 |
| 生活区 | 座椅、床铺、毯子 | 可放小型生活装饰 |
| 工作区 | 台面、工具箱、收音机位置 | 允许放一个主要功能模块 |
| 储藏区 | 箱子、药品架、衣物 | 允许放一个储备类模块 |
| 窗边与墙面 | 窗、照片、灯、地图 | 只允许墙面或小型装饰 |

固定的床、驾驶台和基础储物不需要玩家重新摆放。玩家真正决定的是有限的功能模块和生活物件，避免一开始就变成家具编辑器。

## 6. 首版家具方向

首版建议只验证三件功能家具加若干纯装饰，不要一次加入完整家具商店。

| 家具 | 类型 | 玩家感受 | 规则方向 |
|---|---|---|---|
| 便携工作台 | 功能 | 房车是修理和改装的地方 | 作为工坊入口，服务现有武器解锁/升级，不额外创建一套复杂菜单 |
| 短波电台与地图桌 | 功能 | 玩家能提前听见危险 | 显示波次路线、特殊敌人或远征情报，优先提供信息而不是直接加伤害 |
| 医疗柜 | 功能 | 房车提供恢复和容错 | 增加有限的医疗准备能力；具体是容量、补给还是治疗效率，需和现有医疗规则二选一 |
| 暖色壁灯 | 装饰/氛围 | 进入后立刻感到这是一个家 | 室内提供暖光，外部窗户出现对应光色；首版不直接增加战斗数值 |
| 照片、毯子、杯子、植物、战利品 | 纯装饰 | 让玩家留下旅途痕迹 | 只改变视觉和房车生活感，不能伪装成尚未实现的属性加成 |

功能家具最好是已有系统的实体入口，而不是重复制作“房车工坊界面”和“手册界面”。玩家在空间里找到物件，再打开已经存在或计划中的对应功能。

## 7. 布置规则

- 家具按小网格放置，支持 90 度旋转；不用追求厘米级自由摆放。
- 放置预览显示绿色/红色状态、占地和不能放置的具体原因。
- 入口、过道、窗户、固定床铺和功能台面不能被堵住。
- 功能家具限制为少量插槽，建议首版最多 3 个；这样“放哪一个”比“全部都放”更有意义。
- 纯装饰可以有自己的小型墙面/桌面插槽，避免装饰物和功能家具互相争夺所有空间。
- 已购买家具可以免费移动，拆除或出售不能通过反复操作刷回资源。
- 家具状态用家具 ID、位置、朝向和是否启用记录，不保存 Three.js 对象。

推荐的操作延续现有交互：靠近门按 `E`，布置时沿用点击放置和 `R` 旋转，`Esc` 退出布置或离开室内。首版不新增复杂拖拽、吸附和多层墙体编辑。

## 8. 经济与取舍

不要新增“家具币”。室内家具直接和外部防线竞争现有木材、零件：

- 小型装饰主要消耗木材。
- 功能家具主要消耗零件，并可以少量消耗木材。
- 家具不能免费提供塔伤害、角色伤害和营地生命上限。
- 信息类家具的价值是提前知道危险，治疗类家具的价值是提高容错；它们不应该同时给出强力攻击加成。
- 具体数值最终仍以 `src/rules.ts` 为运行时唯一来源，文档只保留意图和约束。

这样每个白天都会有一个自然的选择：先建外部防线，还是把有限的材料投入到更像家的房车里。两种选择都应能通关，但会产生不同的准备路线。

## 9. 视觉反馈验收

室内功能只有在室外也能被感受到，才值得投入美术成本。至少需要：

- 新增壁灯后，夜间从车窗看到暖色光，而不是房车仍然完全不变。
- 放置地图桌、工作台或医疗柜后，窗内能看到明显剪影或对应颜色。
- 室内进入和退出不闪烁、不穿墙、不把角色送到房车另一侧。
- 室内镜头能看清门、过道、家具占地和互动提示。
- 1280×720 与窄屏下，家具和提示不被 HUD 遮挡。
- 截取统一视角的昼/夜图片，比较室外房车是否仍然是营地视觉中心。

## 10. 最小可玩闭环

### 闭环判断

设计上可以闭环，但必须把房车家具接入下一夜的实际决策。当前代码尚未实现房车内部，因此下面是验收目标，不是已完成事实。

| 环节 | 玩家行为 | 产出 | 下一环节的验证 |
|---|---|---|---|
| 白天获取 | 采集木材、远征获取零件和医疗包 | 获得建设与布置资源 | 决定资源投入外部防线还是房车 |
| 房车取舍 | 进入房车，购买并摆放家具 | 消耗木材/零件，占用有限功能位置 | 不能同时免费拥有所有优势 |
| 准备收益 | 使用工作台、电台或医疗柜 | 武器解锁、波次情报或医疗准备 | 效果必须在下一夜影响玩家选择 |
| 夜晚考验 | 建塔、走位、使用武器和主动能力 | 守住营地或承受损失 | 能看出家具是否真的帮助了防守 |
| 黎明反馈 | 清场后领取资源、专长和恢复 | 家具与外部建设继续成长 | 进入下一天，形成新的取舍 |

闭环成立必须满足以下条件：

- 功能家具必须有明确的下一夜使用场景。工作台可以服务武器解锁，电台必须提供会改变布置决策的波次信息，医疗柜必须提供实际的医疗准备。
- 家具必须消耗共享资源或有限位置，否则玩家没有理由在外部防线和室内之间做选择。
- 家具状态要跨越白天、夜晚和黎明保留；否则玩家的布置不会形成成长感。
- 夜晚结果必须反馈到营地耐久、角色生命、资源或专长，不能只显示“家具生效”。
- 纯装饰可以没有战斗数值，但要通过窗光、剪影和房车外观变化形成情绪上的回报。

最稳妥的第一个可验证闭环是：

`采集零件 → 进入房车 → 放置工作台 → 解锁步枪 → 第三夜用步枪应对破阵者 → 黎明获得新资源 → 继续布置`

第一阶段只需要证明这一条链路成立：

`白天靠近门 → E 进入 → 放置一件家具 → 看到成本与反馈 → 从门离开 → 夜晚窗内显示布置结果 → 正常完成防守`

建议任务拆分如下：

| 任务 | 内容 | 状态 |
|---|---|---|
| RV-01 | 锁定室内布局、视角和日/夜进入规则 | TODO |
| RV-02 | 门交互、进入/退出过渡和室内状态 | PARTIAL（门交互/状态已验证，镜头过渡未实现） |
| RV-03 | 家具数据、网格放置、旋转、阻挡和撤销 | TODO |
| RV-04 | 工作台、电台、医疗柜三件功能家具 | TODO |
| RV-05 | 窗光、窗内剪影和室外反馈 | TODO |
| RV-06 | 昼夜循环、资源取舍、窄屏和存档验收 | TODO |

在 RV-02 和 RV-03 没有实际可操作闭环前，不应先扩展家具数量或做家具等级树。

## 11. 暂不做

- 房车内部战斗和敌人进入室内。
- 多辆房车、多个可进入建筑。
- 家具旋转碰撞的完全自由编辑器。
- 复杂电力、重量、供水、饥饿和房车驾驶系统。
- 通过装饰数量直接堆叠伤害、射速或敌人减速。
- 为室内单独制作一张资源地图或另一套昼夜战役。

## 12. 需要确认的选择

在进入实现前，剩余需要确认三点：

1. 是否接受室内采用固定切面/独立小场景，而不是完全连续的房车内部 3D 漫游？
2. 三个功能家具是否先定为工作台、电台、医疗柜？
3. 是否接受家具和外部建筑共用木材、零件，形成真正的准备取舍？

白天进入规则已经确认。如果剩余三点也确认，房车内部就不只是好看的附加房间，而会成为“为什么要守住这个地方”的第二个情感支点。
