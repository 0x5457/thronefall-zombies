# PINEFALL 开发路线图

> 本文是可执行的开发计划与任务拆分；具体数值以 `src/rules.js` 为运行时唯一来源。
> 状态：TODO / DOING / PARTIAL / VERIFY / DONE / BLOCKED（在 `DEVELOPMENT.md` 跟踪）。
> 设计目标变更先改 `GAME_DESIGN.md`，再改本文任务，最后动代码。

## 0. 产品形态（决定）

- **形态：Thronefall 式短局重玩**。一局 5 夜、约 20–30 分钟；靠"评分 + 恶兆 + 解锁 + 构筑组合"产生重复可玩性，而不是靠线性剧情拉长。
- **核心幻想**：白天用有限资源把营地变成防线，夜晚亲自守住它，天亮时知道自己为什么赢/为什么输。
- **核心体验目标**：每一夜都是一道可预判、需要构筑解答的战术题；失败能解释，重开能改进，改进能变强。
- **暂不采用**：开放世界、多人、程序化无限内容、大型剧情战役（作为发行后扩展方向）。

## 1. 现状诊断（为什么像 demo）

| 问题 | 证据 | 对应任务 |
|---|---|---|
| 夜晚没有题面：敌人只是走固定路线的数值块 | 夜 1 仅 10 游荡者；行为只有速度/护甲差异 | NGT-01/02 |
| 资源不缺，选择不痛 | 开局 80 木 + 每日 35；塔 35、栅栏 15，几乎"全都要" | ECO-01/02/03 |
| 情报看了没用 | 情报页只有组成与数量，缺"该带什么/该防哪里" | NGT-03 |
| 建筑只有数值升级 | 升级 = +血 +伤害，没有分支与协同 | BLD-01/02 |
| 玩家操作空间小 | 自动射击 + 固定路线，走位收益低 | SKL-01/02/03 |
| 失败无痛、没有重玩理由 | 倒地只扣 15 营地；无评分、无变体、无跨局解锁 | META-01/02/03 |
| 世界只有营地 | 外围 180×180 无地标；远征是菜单数字 | WLD-01/02 |

## 3. 里程碑

1. **M1 可玩性拐点（当前）**：Phase 1 全部 + ECO-01/03 + META-01。验收：前两夜需要真实取舍与针对性准备，玩家能说出"我为什么输"。
2. **M2 重玩拐点**：Phase 2 剩余 + Phase 3 + META-02。验收：同一夜换构筑/恶兆有不同解法。
3. **M3 手感与技巧**：Phase 4 + WLD-02。验收：玩家操作能显著改变战局。
4. **M4 世界与叙事**：Phase 6。验收：营地与外围有可探索内容与情感回报。
5. **M5 发行**：Phase 7 全部。

## 4. 每任务执行流程

1. 读 `GAME_DESIGN.md` 相关章节 → 必要时先改设计。
2. 规则改动先写 `src/rules.js` + `tests/*.test.js`（Node 内置测试）。
3. 场景/UI 接入后跑 `npm test`、`npm run build`，再跑相关浏览器测试（`tests/*.browser.js`），必要时新增。
4. 更新 `docs/DEVELOPMENT.md`（状态/证据/下一步）与 `docs/DEVLOG.md`。
5. 画面改动保存同视角昼夜截图到 `artifacts/`；未实测不宣称帧率。
